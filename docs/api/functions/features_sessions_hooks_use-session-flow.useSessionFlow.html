      Database side-effects for an ongoing session: creating the sessoes row, persisting executed exercises into execucoes_exercicio, and closing the session. All writes go through the authenticated client (RLS applies).

      • finalizeSessionAutoFill: (
            sessaoId: string,
            totalSeconds: number,
            fugaIntervals: { end: number; start: number }[],
        ) => Promise<void>

        On session end, writes the total time to sessoes.tempo_total and replicates the auto-filled values into the session's Control Record:

        • "Tempo da sessão" question → total in seconds;
        • "Fugas (número de fugas e tempo do ocorrido)" question → " - (mm:ss,mm:ss), ...", using the total stopwatch start/end. These questions are not shown during execution (they are filled here) but can be edited later in the Control Record from the history.
      • finishSession: (sessaoId: string, __namedParameters?: FinishSessionInput) => Promise<void>

        Marks a session as completed or cancelled with an optional reason.

      • finishSessionAndSaveUnexecuted: (
            sessaoId: string,
            motivo?: MotivoNaoRealizacao,
            descricao?: string,
        ) => Promise<void>

        Finishes an in-progress session from outside the execution screen (e.g. when starting a new concurrent session). Marks it as completed and, for structured circuits, records the unexecuted exercises as 'nao_realizada' with a default reason/description. Reads everything from the database — it does not depend on the session screen's in-memory state.
